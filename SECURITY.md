# Security reporting

Report suspected vulnerabilities privately to the project maintainer, Brian Kyanjo, at **bkyanjo3@gatech.edu**. If GitHub's private vulnerability-reporting option is available for this repository, it may also be used. Do not put exploit details or credentials in a public issue.

Include affected revisions, files, a minimal reproduction, expected impact, and sanitized environment details. Relevant areas include installer downloads and command execution, configuration parsing, filesystem paths, dependency specifications, and handling of credentials or build environments.

Scientific correctness and ordinary installation failures belong in normal issues. For ICESEE source concerns, also see [the bundled ICESEE security policy](ICESEE/SECURITY.md). Vulnerabilities in external models or Spack itself should be reported to their maintainers according to their policies. This document does not imply that all historical releases receive security fixes.
